- **Closing-phase review gap.** Resilience + test lanes were integrated on independent locks + the PM gate but initially **skipped the formal REVIEW_CODE/REVIEW_ARCH passes** — caught by the operator, corrected by dispatching both before CLOSE.

- Both governance gate "failures" at CLOSE were **environment/infra**, not code — a reminder to diagnose gate failures to root cause before treating them as sprint defects (`verify-before-claiming`).
- The `wl9s4v` bug severity was runtime-dependent (throw on ≤8.x M.E.DI, silent-skip on 9/10) — diagnosis accuracy mattered for honest docs.
