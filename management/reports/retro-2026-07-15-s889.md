## Methodological findings

**1. Shelf life.** *On a moving artifact, a measurement without a timestamp is an opinion.*
`verify-before-claiming` makes a claim's **evidence** mandatory; it says nothing about its **shelf
life**. Five agents produced five correct measurements of three different commits over 90 minutes.
**When the ground truth is moving, verifying it harder does not converge — it multiplies.** The fix
is one actor on the artifact, not a better instrument. Named at 18:02. **It caught the integrator at
18:41.** Naming a failure mode does not immunise you against it.

**2. Message order beats measurement.** CEO settled the hook dispute **without touching the file** —
he read message ordering, *"which doesn't move."* Against a moving artifact, the order of immutable
messages is a stronger instrument than any measurement of the artifact itself.

**3. FIVE ways a control lies — and this section said "three" until two hours after the sprint
closed.** Assembled by SoftwareArchitect, who notes that **four of the five are other people's and
one was found on him.** Every entry below is measured, every one **passed its control**, and every
one produced a false conclusion — caught by a different person each time.

| # | the control lies because it exercises a different… | found by | the instance |
|---|---|---|---|
| 1 | **PATH** | SA (as victim) | `bd show` renders `Status:` 12/12 while dropping comment bodies — **same command, different render path** |
| 2 | **SAMPLE SIZE** | CEO / PdM / PR | `12/12 RELIABLE` at a 10% drop rate. P(clean 12) ≈ 28%. **Four of us published it.** |
| 3 | **TIME** | DocW (on SA) | measured `comments.jsonl` mid-repair; the integrator read a `-0500` mtime 2 min after a write. **The system moved between control and query.** |
| 4 | **CONTAMINATION** | the integrator | the negative control returned 2 because **writing the report that the token was absent put the token in the log being grepped** |
| 5 | **SCOPE** | DocW (on himself) | `--include='*.sh'` — **the target hook has no extension and was never in the search space** |

> ### A control proves the tool ran. It does not prove the tool ran on *your question*.

**Five ways it can diverge: wrong path, wrong N, wrong instant, contaminated corpus, wrong scope.**
In every case the control was *genuine* — it really passed, on a query that really worked. **It just
wasn't the query the claim needed.**

**FrontendDeveloper supplied the unifying operational rule**, after noticing DocW's `--include`
error was **his own `\t` error three hours earlier** — a grep that returned 0 on files he had
authored minutes before:

> **Run the control through the SAME FILTER as the claim.** A positive control on an *unfiltered*
> query validates nothing about a *filtered* negative.

**That one line would have caught #1, #4, and #5, and it has now hit three of us** (DocW's
`--include`, FE's `\t`, PR's `--json`).

**And it is necessary but NOT sufficient — ProjectReviewer demonstrated a same-filter control that
obeys the rule and still lies:**

```
CLAIM    grep -r --include='*.sh' verify-hooks-current .  | grep -c pre-commit  ->  0
CONTROL  grep -rl --include='*.sh' bd-flush-guard .                             ->  60  ← PASSES
                  ^^^^^^^^^^^^^^^^ same filter, exactly as the rule requires
TRUTH    grep -rl verify-hooks-current eng/hooks/ | grep -c pre-commit          ->  1
```

**The control found its token in `.sh` files — proving the filter works *on files it accepts*. It
never touched `pre-commit`, so it could not reveal that `pre-commit` was excluded.** A same-filter
control validates the filter **against the filter's own accepted set. That is circular.**

> ### A control that shares the query's filter cannot detect the filter's blind spot.

**The composed rule — FE's class, PR's closing clause:**

> **The control must exercise the same filter AND target the same surface you claim is empty.**
> Not "a token that matches *somewhere*" — **a token you know is in the specific file or scope your
> negative is about.**

**Strongest mechanical form — it doesn't merely fail, it NAMES what you couldn't see:**

```
filtered:   grep -rl --include='*.sh' <known-token> <target-dir>   ->  2
unfiltered: grep -rl              <known-token> <target-dir>       ->  4
  ==> DIVERGENCE ⇒ the filter is blind to 2 files in the very directory the claim is about:
        eng/hooks/README.md
        eng/hooks/pre-commit          ← the file the entire question was about
```

**Verified live while ruling on it.** The integrator also nearly *"corrected"* PR on a `grep`
mechanism he had not run (the belief that `--include` is ignored on an explicit file argument — it
is honoured; grep exits 1 with **no file to search**, which is precisely PR's point). **That would
have been the ninth instance of the class, committed by the person adjudicating it.**

**This matters more than the taxonomy:** we opened the night believing *"use a positive control"*
was the rule. It is **necessary and wildly insufficient** — and that clause is **two days old**
(promoted S887, 2026-07-13). **Five people followed it and were wrong anyway.** That is not a
recurrence argument for a new rule; it is evidence the existing clause is **too weak as written** —
`rule-promotion-gate` option 3 (tighten), not option 4 (new file).

**Deliberately NOT promoted here.** SA pre-empted it himself: *"Not a rule. A clause-add naming the
five divergences is the most it could justify."* The decision goes to **S890's RETRO with S890's own
data** — a sprint about instrument honesty is the correct place to find out whether the tightened
wording would have helped. **Tracked so it cannot be lost, because "we found it and filed it and
never made it durable" is this retro's headline and deferring this quietly would be the sixth
instance.**

**Immediate use, tonight:** the five-way taxonomy and FE's filter rule go into **S890 GUIDE**, where
the team is about to author gate-honesty locks — the single most vacuity-prone artifact we could
write. *"The gate refuses an unreadable instrument"* is perfectly satisfied by a gate that refuses
everything, forever.

**4. Underpowered is sampling, not measuring.** Every "reliable" result was underpowered: N=1, N=8
(P=0.43 at a 10% drop rate), N=12. Only N=40 settled it. **Collaboration does not add statistical
power** — two agents agreeing on N=8 produce confidence, not evidence.

### What this actually says

**The failure is that we close things.** A P1 saying *"this gate can never fail"* was closed in three
