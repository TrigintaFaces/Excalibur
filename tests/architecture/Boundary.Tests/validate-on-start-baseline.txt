# These eight entries retain their reviewed exception reasons from the historical bd-ccr9eg burn-down.
# This list does not establish that every registration gap has been eliminated. The bounded detector
# reports supported gaps and unresolved composition separately; neither this list nor an unresolved
# result proves repository-wide startup-validation coverage.

# --- Category 1: NO top-level invariant (single bool / independent optionals / unconstrained value;
#     nested option objects self-validate). A validator would be vacuous, so per the Step-0 ruling these
#     are documented allowlist entries rather than faked validators. ---
#
# AwsSqsFifoOptions: single bool (ContentBasedDeduplication) — a bool cannot be invalid.
Excalibur.Dispatch.Transport.Aws.AwsSqsFifoOptions
# DispatchPatternsJsonOptions: get-only SerializerOptions + optional SerializerContext — nothing to reject.
Excalibur.Dispatch.Patterns.DispatchPatternsJsonOptions
# IndexManagementOptions: REMOVED from the baseline — it now has a real IValidateOptions<T>.
# The entry's original rationale was "nested option objects that self-validate", and that was not the
# case: none of DefaultTemplateOptions, LifecycleManagementOptions, OptimizationOptions or
# EnvironmentOptions had a validator or any in-type check. The values are bound from configuration, so
# a shard count of zero or a non-positive refresh interval could reach Elasticsearch and fail at
# index-creation time instead of at startup. IndexManagementOptionsValidator now rejects those.
# UpcastingOptions: single bool (EnableAutoUpcastOnReplay) — a bool cannot be invalid.
Excalibur.Dispatch.Versioning.UpcastingOptions
#
# --- Category 2: FRAMEWORK-OWNED options — registered + validated by a Microsoft/first-party handler.
#     The bounded detector does not trace that handler's composition. Framework-owned validation
#     does not require a validator written by this repository; predicates and annotations also count
#     as validation when their registration profile is supported by the detector. ---
#
# HttpStandardResilienceOptions: Microsoft.Extensions.Http.Resilience — registered by the framework's
#   AddStandardResilienceHandler (adopted by the Datadog/Splunk audit sinks, b7i6rh). Microsoft owns the
#   type and its validation; we do not (and must not) add our own validator for it. Intentional exemption
#   tracked as hcpupz.
Microsoft.Extensions.Http.Resilience.HttpStandardResilienceOptions
# DeadLetterOptions (GooglePubSub): three surviving properties after the inert ones were removed --
# two optional nullable resource names and a get-only initialized set. The names are optional until the
# DLQ is used and are guarded at point of use in PubSubDeadLetterQueueManager; the set cannot be invalid.
# The former validator checked only properties that no longer exist, so it was deleted rather than
# refilled with a vacuous body.
Excalibur.Dispatch.Transport.Google.DeadLetterOptions
# MqttCloudEventOptions: ONE property, a bool (Retain). A bool has no invalid value, so a validator for
# this type could only ever return Success -- the vacuous body the two entries above were deleted rather
# than given. Same disposition, and more clear-cut: there is nothing here to check, not merely nothing
# left after a removal. If a constrained property is ever added, remove this line and write the validator;
# the guard fails when a baselined type becomes fully validated, so it will force that.
Excalibur.Dispatch.Transport.Mqtt.MqttCloudEventOptions
# AzureEventHubsCloudEventOptions: two surviving properties after the inert ones were removed. Its former
# validator checked six properties, all of which are gone. Same disposition as DeadLetterOptions.
Excalibur.Dispatch.Transport.Azure.AzureEventHubsCloudEventOptions
