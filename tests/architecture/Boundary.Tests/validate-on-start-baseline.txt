# AwsSqsFifoOptions: single bool (ContentBasedDeduplication) — a bool cannot be invalid.
AwsSqsFifoOptions
# DispatchPatternsJsonOptions: get-only SerializerOptions + optional SerializerContext — nothing to reject.
DispatchPatternsJsonOptions
# IndexManagementOptions: REMOVED from the baseline — it now has a real IValidateOptions<T>.
# The entry's original rationale was "nested option objects that self-validate", and that was not the
# case: none of DefaultTemplateOptions, LifecycleManagementOptions, OptimizationOptions or
# EnvironmentOptions had a validator or any in-type check. The values are bound from configuration, so
# a shard count of zero or a non-positive refresh interval could reach Elasticsearch and fail at
# index-creation time instead of at startup. IndexManagementOptionsValidator now rejects those.
# InMemoryEventStoreOptions: single optional IJsonTypeInfoResolver (EventTypeInfoResolver). Null selects
#   the reflection serialization path and ANY non-null resolver is structurally valid, so there is no
#   value a validator could reject -- the same shape as DispatchPatternsJsonOptions above. Whether a
#   resolver actually DECLARES a given event type is knowable only per-append against the consumer's own
#   runtime types, never at startup, and the store already fails that closed where it is knowable:
#   ResolvedEventPayload raises EventTypeNotDeclaredException rather than writing. A startup validator
#   here could only return Success, which is the faked validator the Step-0 ruling rejects.
InMemoryEventStoreOptions
# SagaInstrumentationOptions: two bools (EnableMetrics/EnableTracing) — no invariant.
SagaInstrumentationOptions
# UpcastingOptions: single bool (EnableAutoUpcastOnReplay) — a bool cannot be invalid.
UpcastingOptions

HttpStandardResilienceOptions

# The former validator checked only properties that no longer exist, so it was deleted rather than
# refilled with a vacuous body.
DeadLetterOptions

AzureEventHubsCloudEventOptions
