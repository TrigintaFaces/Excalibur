# --- ACCEPTED: genuinely un-observable-from-IL cases. Each carries its own rationale above it. ---
#
# There are TWO legitimate shapes here, not one. The preamble at the top of this file names only the
# first, because the second was not known when it was written:
#
#   (1) The value is read by something the census cannot SEE -- a configuration binder or reflection,
#       which leaves no getter call site at all. Blind spot (2) on OptionLivenessScanner.ScanResult.
#
#   (2) The value is read by something the census deliberately EXCLUDES -- the option's own
#       IValidateOptions -- and for this option that read IS the behaviour. The exclusion exists
#       because validating a value the framework then never observes is the lie this census hunts.
#       That reasoning holds for a value the framework was supposed to USE (range-checking a batch
#       size does not make anything batch). It does NOT hold for an escape-hatch flag whose entire
#       contract is to gate a startup refusal: there is no downstream consumer BY DESIGN, and the
#       refusal is externally observable -- the host does not start. IL cannot tell the two apart,
#       because both compile to a getter read inside a validator, so the split is made here and each
#       entry names the test that proves the refusal still fires.
#
#   (3) The value is read by an implementation the CONSUMER supplies of a framework interface the
#       framework does not implement. The registration exists to configure that class, and the
#       reader is in the consumer's assembly, so no shipped IL can contain the getter call. This is
#       distinguishable from a defect the same way (1) and (2) are: the interface has ZERO shipped
#       implementations, so there is no framework component that was supposed to read the value and
#       failed to. Each entry names the test that resolves a stand-in implementation through the
#       real registration and asserts it observes the configured values, and that the startup
#       refusal still fires.
#
# Excalibur.Data.ElasticSearch.Security.KeyManagementOptions::Provider
#   The key provider is selected during service registration, before any options instance exists, by
#   reading the configuration value directly:
#   src/Excalibur/Excalibur.Data.ElasticSearch/Security/SecurityServiceCollectionExtensions.cs:161-162
#   takes both the typed value and the raw string, because an ABSENT key binds to the zero-valued enum
#   member and must be distinguishable from a consumer deliberately naming it. That read is against the
#   IConfiguration section, not the bound property, so it leaves no getter call site for the census --
#   blind spot (2) on OptionLivenessScanner.ScanResult. The value IS observed and it DOES change
#   behaviour: it selects the arm of the provider switch, and a value with no arm is refused at
#   registration. Locked by KeyManagementConfigurationBindingShould.
