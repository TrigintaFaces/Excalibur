# Transport receiver conformance coverage baseline.
#
# One exact owningProject|namespace::OuterType|ArmName identity per entry. Blank/comment lines are
# ignored. This is a shrink-only historical debt list: an entry here records that the suite NEVER CALLS
# that arm, so the arm cannot fail for that transport and its green says nothing about it.
#
# AN ENTRY IS NOT ACCEPTED COVERAGE. Read it as a work item: either the arm is meaningful for that
# transport and nobody wrote the call, or it is genuinely inapplicable and no one has yet said so in
# writing. Both are open; the list does not distinguish them, and it deliberately cannot, because a
# self-declared "inapplicable" is the regress this guard exists to stop.
#
# Measured when the guard landed: of the eight transports with a settlement suite, RabbitMQ called all
# six settlement arms and Pulsar called one of six.
#
# THE SUBSTRATE QUESTION, recorded rather than answered. TransportReceiverConformanceTests is a library
# of callable helpers, not a suite that drives its own arms, which is why hand-picking is possible at
# all. Making the kit drive its arms would delete this baseline and this guard together. That is a
# larger change than the gap it closes, and it is tracked as Excalibur_Dispatch-h49vjl rather than
# attempted here.
#
# WHAT THESE ENTRIES COST, so nobody reads the list as bookkeeping. The settlement semantics in
# src/Dispatch/Excalibur.Dispatch.Transport.Abstractions/ARCHITECTURE.md carry a nine-row per-transport
# table asserting each transport's redelivery and retryability axes. Its Evidence section lists only
# reconnection tests and names no settlement arm. So the rows below are the arms that would substantiate
# that table, for the transports that never run them.
