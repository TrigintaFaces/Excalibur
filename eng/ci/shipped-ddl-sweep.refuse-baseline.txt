# shipped-ddl-sweep REFUSE baseline.
#
# Each non-comment line is a table the sweep currently REFUSEs on — it RAN but could not evaluate that
# table's shipped DDL against a write path (an unmapped table, or a mapped one whose write the column
# extractor can't parse). A REFUSE is the gate WORKING (announcing a coverage gap), NOT failing.
#
# The wired gate (shipped-ddl-sweep-gate.sh) enforces this as a SET, not a count:
#   * A table ENTERING this set (a NEW gap) FAILs the gate — a count would be blind to substitution
#     (map one table, a schema change adds another, count unchanged, the new gap invisible).
#   * A table LEAVING (now evaluable) is a reviewable diff: delete its line here.
#
# EVERY line here MUST have a tracked bead naming the table and the write path it could not map —
# an un-owned REFUSE decays into a tolerated red, indistinguishable from a gate that never ran.
# A line is closed by MAPPING the table or scoping it out with a written reason — never by suppression.
#
# Format: the sweep's REFUSE label, verbatim (everything after "REFUSE " up to the " — " explanation).
#
# THE SET IS CURRENTLY EMPTY. Both fence tables left it: the sweep now evaluates
# public.outbox_fence and dbo.OutboxFence on every run, at 2 written/read columns against 2
# declared each.
#
# An empty set is NOT a weaker gate here, and the reason is worth stating because "no entries"
# reads like "nothing is being checked". Vacuity is caught by the wrapper's LIVENESS arm, which
# fails when the sweep reports zero evaluated-table lines -- a sweep that skipped, hung or died
# reds the build whatever this file contains. This file answers a different question: which
# coverage gaps are ACCEPTED. Today, none are.
#
# Adding a line here is still the reviewable act it always was: a table ENTERING the REFUSE set
# fails the gate until someone maps it, or records it here with a written reason and a filed
# issue. Do not add one to clear a red.
