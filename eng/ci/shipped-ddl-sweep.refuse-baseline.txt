# shipped-ddl-sweep REFUSE baseline.
#
# Each non-comment line is a table the sweep currently REFUSEs on — it RAN but could not evaluate that
# table's shipped DDL against a write path (an unmapped table, or a mapped one whose write the column
# extractor can't parse). A REFUSE is the gate WORKING (announcing a coverage gap), NOT failing.
#
# The wired gate (shipped-ddl-sweep-gate.sh) enforces this as a SET, not a count:
#   * A table ENTERING this set (a NEW gap) FAILs the gate — a count would be blind to substitution
#     (map one table, a schema change adds another, count unchanged, the new gap invisible).
#   * A table LEAVING (now evaluable) is a reviewable diff: delete its line here.
#
# EVERY line here MUST have a tracked bead naming the table and the write path it could not map —
# an un-owned REFUSE decays into a tolerated red, indistinguishable from a gate that never ran.
# A line is closed by MAPPING the table or scoping it out with a written reason — never by suppression.
#
# Format: the sweep's REFUSE label, verbatim (everything after "REFUSE " up to the " — " explanation).
#
# SUPERSEDED NOTE: this file used to read "THE SET IS CURRENTLY EMPTY. Both fence tables left it: the
# sweep now evaluates public.outbox_fence and dbo.OutboxFence on every run, at 2 written/read columns
# against 2 declared each." That remains true of the fence tables; the set is no longer empty.
#
# ERASURE DESTROYED-KEY RECORD -- both spellings. The TABLE is fine and that was checked rather than
# assumed: its shipped DDL declares exactly RequestId/KeyHandle/DestroyedAt with the composite primary
# key, in both the provisioning script and the migration document, and those are precisely the three
# columns the write path uses.
#
# WHAT THE SWEEP CANNOT DO IS SCOPE IT. The write path lives in a store class that writes SEVERAL
# compliance tables and JOINS the request table to the destroyed-key table, so the column extractor
# attributes request columns -- certificate id, completion and cancellation fields -- to this table and
# reports drift that does not exist. Mapping it was ATTEMPTED and reverted for that reason: it converts a
# REFUSE into a FAIL built on misattributed columns, which is worse than an announced coverage gap.
#
# A line is closed by MAPPING the table, and closing this one needs the extractor to scope columns to the
# statement naming the table rather than to the file -- or the destroyed-key writes moved to their own
# request class, which the repository already does for other seams. Tracked in the issue tracker against
# this file; no identifier is written here because eng/** is copied to the public mirror.
compliance.ErasureDestroyedKeys
compliance.erasure_destroyed_keys
#
# An empty set is NOT a weaker gate here, and the reason is worth stating because "no entries"
# reads like "nothing is being checked". Vacuity is caught by the wrapper's LIVENESS arm, which
# fails when the sweep reports zero evaluated-table lines -- a sweep that skipped, hung or died
# reds the build whatever this file contains. This file answers a different question: which
# coverage gaps are ACCEPTED. Today, none are.
#
# Adding a line here is still the reviewable act it always was: a table ENTERING the REFUSE set
# fails the gate until someone maps it, or records it here with a written reason and a filed
# issue. Do not add one to clear a red.

# THE GLOBAL POSITION COUNTER TABLES.
#
# One counter per event store, the seam that makes the global stream gapless. The sweep RUNS against
# each and cannot evaluate it: the counter is written by
#   UPDATE <counter> SET Value = Value + @Count WHERE Id = 1 RETURNING Value
# and the column extractor recognises only an INSERT column list, so it reports src-written-cols=0.
# Mapping them does not clear it -- a mapped table whose write cannot be parsed refuses just the same.
#
# This is a gap in the EXTRACTOR, not in the shipped DDL: every create script and every shipped sample
# declares the counter with both of its columns (Id and Value). DELETE THESE LINES once the extractor
# reads an UPDATE ... SET column list, at which point all five evaluate on every run.
Events_Position
events_position
dbo.EventsPosition
events.EventsPosition
