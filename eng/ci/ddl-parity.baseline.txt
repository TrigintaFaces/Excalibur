# ddl-parity baseline — KNOWN provider-sibling DDL gaps, tracked, not forgiven.
#
# Each line is "<family>:<provider>" for a RELATIONAL provider package that ships no .sql
# while a relational sibling in the same family ships one. These are real consumer-facing
# gaps: a consumer installing the package cannot obtain the schema needed to run it, and the
# framework does not auto-create tables.
#
# This file exists so the parity check can go live NOW against a tree that already has gaps,
# without either (a) failing every commit until the DDL is authored, or (b) being weakened
# into a warning that nobody reads. A listed gap is ALLOWED. Any gap NOT listed FAILS.
#
# Adding a line is a deliberate act and must reference the bead that will close it.
# Removing a line is what "fixed" looks like. The set only shrinks.
#
# THE BASELINE IS ALSO CHECKED IN THE OTHER DIRECTION: a line here that is no longer a gap
# (the DDL got authored) FAILS as STALE, so this file cannot silently accumulate entries that
# forgive nothing. A suppression list nobody prunes becomes a way to hide the next regression.

# appears without a script. It is listed because operators who provision schema separately,
# and run the application without table-creation rights, still have nothing to run — the same
# reason the SqlServer provider requires an explicit script rather than auto-creating.

# NOT A GAP, and this entry differs in kind from the two above: it is not deferred work and no
# bead will close it, because there is no schema for this package to ship.
#
# Excalibur.Data.MySql is a connection-layer package. It contains a persistence provider, a health
# check, pooling and retry options and a transaction scope, and nothing else — no store, no table
# name option, and no statement of any kind: grep finds zero INSERT, zero SELECT and zero
# CREATE TABLE across its sources. A consumer installing it cannot fail on a missing table because
# it never addresses one.
#
# It began failing the parity check when its relational siblings Data.SqlServer and Data.Postgres
# started shipping dead-letter DDL, which is the check behaving exactly as intended: it compares
# packages by family and cannot know that this sibling has no store behind it. That distinction has
# to be recorded by a human, so it is recorded here.
#
# If a store is ever added to this package, DELETE THIS ENTRY rather than extending it. The reason
# above stops being true the moment the package writes to a table.
