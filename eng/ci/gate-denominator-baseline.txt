# gate-denominator-baseline.txt — gate scripts that do not yet report WHAT THEY EXAMINED.
#
# Read gate-denominator-gate.sh for the why. In one line: a gate that prints only what it FOUND
# cannot be told apart from a gate whose matcher stopped matching, because both print the same
# green. The fix is one counter and one line — `EXAMINED: <n> <label>` — emitted over the real tree
# at the moment of the verdict, via gate_denominator() in gate-denominator.sh.
#
# TWO SECTIONS, and they mean different things.
#
#   NOT A GATE      — a helper, census, report generator, or manually-run tool. It renders no
#                     pass/fail verdict, so there is no green for a zero denominator to forge.
#                     These are permanent entries, not debt.
#
#   TRACKED DEBT    — a real gate that DOES render a verdict and does NOT yet say what it examined.
#                     THIS SECTION IS A SHRINK TARGET. Migrating a gate deletes its line here.
#
# Adding a NEW gate to the debt section is an explicit, reviewed admission — the default expectation
# for a new gate is that it reports its denominator on the day it lands.
#
# HOW TO MIGRATE ONE (about four lines):
#   1. source the helper:  . "$(dirname "${BASH_SOURCE[0]}")/gate-denominator.sh"
#   2. count the POPULATION the gate walks — NOT the findings. This is the step that goes wrong:
#      where the good outcome is "0 findings", the finding count can never distinguish a clean tree
#      from a scan that read nothing. Count the files/symbols/candidates examined. (Caught live
#      during this file being written: a first attempt counted files-carrying-a-skip, which is zero
#      on a healthy tree, and the gate refused its own passing self-test arms.)
#   3. call gate_denominator "$count" "<label>" || return/exit 2   before the verdict
#      (gate_denominator_may_be_empty ONLY where the population is a diff and zero is normal)
#   4. delete the line below.
#
# Format: one basename per line. Blank lines and #-comments ignored.
