# ide0052-baseline.txt — the measured population of unread private members in src/ at the moment
# IDE0052 was re-armed. See eng/ci/ide0052-ratchet-gate.sh.
#
# THIS FILE IS A DEBT LEDGER WITH A RATCHET, NOT AN ALLOWLIST.
#   - An entry here is NOT blessed. It is a member the compiler says is assigned and never read,
#     recorded so the detector could be turned back on without redding every build on day one.
#   - A site NOT listed here FAILS the gate on first appearance. That is the safety arm.
#   - Cleaning a site should DELETE its line. A stale entry (site no longer reported) is a warning,
#     not a failure, so that fixing one in a parallel change never reds CI on a race.
#
# HOW THIS POPULATION WAS PRODUCED, so it can be reproduced rather than trusted:
#   dotnet build Excalibur.sln -c Release --no-restore --no-incremental \
#       -p:TreatWarningsAsErrors=false -p:BuildExamplesAndTests=true
#   --no-incremental matters: an incremental build does not re-run analyzers on unchanged projects,
#   so a census taken without it silently under-reports. BuildExamplesAndTests=true matters too --
#   without it three of the entries below (Excalibur.Testing, Outbox.CosmosDb) are not compiled at
#   all and the gate reports them STALE, which on a partial log means "not scanned", never "fixed".
#   New-site detection is unaffected by log completeness; only the stale arm needs the full build.
#
# KEYED BY FILE + MEMBER, DELIBERATELY NOT BY LINE. A line-keyed baseline goes stale on every edit
# above a site and manufactures false ratchet failures that train people to regenerate it blindly.
#
# WHAT AN ENTRY MEANS AND DOES NOT MEAN: the compiler proved the value assigned to this member is
# never read. It does NOT say whether that is a dead field or a live dependency someone forgot to
# use — those need different fixes and only a human can tell them apart. Several entries below are
# the second kind (a handler never invoked, a timeout never applied, a serializer option never
# passed); they are release-class defects, not cleanup, and are tracked separately.
#
# NOT COVERED BY THIS POPULATION, stated so nobody reads its silence as a clean bill:
#   - tests/**   — tests/Directory.Build.props sets EnforceCodeStyleInBuild=false, so IDE analyzers
#                  never run there at all. Measured, not assumed: a planted probe emitted CS0414 and
#                  no IDE diagnostic.
#   - members already carrying a #pragma/SuppressMessage for IDE0052 — suppressed at the site, so
#     they never reach this list. Audited separately.
#   - unread primary-constructor PARAMETERS — those are CS9113, a different diagnostic, itself set
#     to suggestion in .editorconfig.
#
